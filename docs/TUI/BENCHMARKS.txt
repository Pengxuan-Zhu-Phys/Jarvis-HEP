Jarvis Monitor TUI — appearance canvases
========================================

These plain-text frames are the drawing board. Edit them. The next round of
the TUI is driven by (1) your edits in these files and (2) what you tell me
in chat. Data inside is fake. Colour does not exist here; we are locking
layout, density, truncation, and scale behaviour.

Do not wrap. Do not add or delete lines unless you are changing a benchmark
height on purpose. Every file in a folder named *-WxH/ is exactly W columns
by H rows. Check with:

    python3 docs/TUI/_check.py

Type ramp (named schemes, not hex): docs/TUI/STYLES.txt
Say the scheme name when asking for a visual change (topbar, hint, tab-active, …).

How to iterate
--------------

1. Open docs/TUI/ref-120x36/0-splash.txt first (Agent home), then 1-overview.txt.
   Monospace editor, wrap OFF, whitespace ON.
2. Draw. Keep each line exactly 120 characters, 36 lines.
3. Tell me what you changed, or just say "look at overview". I will
   propagate the idea to the other benchmark sizes and, later, to Textual.
4. When a min/wide/ultra frame looks wrong after a ref edit, say which
   size and I will restack that frame. Do not try to keep five sizes in
   sync by hand unless you want to.

_mint.py regenerates EVERY canvas from fake data and will wipe hand
edits. Do not run it once you have started drawing.

_check.py only measures width and height. Safe anytime.


Scale rules already sketched in these frames
--------------------------------------------

80 cols   abbreviated tabs (Over Wrk Fac Spl Cal Sam Host), drop redis
          endpoint, drop RSS/CALC columns, spark labels smp/que/cpu.
120 cols  full tab names, 2x2 overview, 8 table columns, right pane ~40.
160 cols  overview becomes 4 columns + running-sample strip.
220 cols  same 4 columns, wider bars, longer spark history, more running rows.
24 rows   2x2 is 4+4, three spark lines, two live lines, no spare air.
36 rows   design density.
48/64     extra height goes to tables and the running strip, not new pages.
